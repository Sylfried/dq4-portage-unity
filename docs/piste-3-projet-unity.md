# Piste 3 : projet Unity reconstruit (essai), fiche de reprise

Fiche de reprise du dépôt **dq4-portage-unity** (version Unity du portage de DQ4 Android). Lire aussi `notes-technique-portage-dq4.md` (protocole moteur -> Unity). Ce dépôt est issu de `dq4-pc` (privé), où se trouvent encore la visionneuse pyglet native (`fenetre.py`, `ui_menu.py`, `son.py`), ses notes (`notes-visionneuse-dq4-pc.md`) et les outils d'extraction du code Unity d'origine (`outils/ui_il2cpp`) : les renvois à la « visionneuse » dans les notes visent ce dépôt-là. Historique des issues (#57 = cette piste) : dépôt `dq4-pc`.

## Objectif
Tester si **Unity lui-même** (Éditeur 2022.3.62f3, licence Personal gratuite) peut servir d'afficheur à la place de notre visionneuse pyglet : le moteur original (`libdq4core.so`) reste émulé en Python et pilote une scène Unity, avec le rendu, les caméras et l'interface en 16:9 natif (Canvas Scaler) faits par Unity. Ce n'est **pas** un remplacement de la piste 1 (continuer la visionneuse en lisant le code Unity d'origine) : les deux avancent en parallèle, on compare ensuite.

## Ce qui est acquis (à réutiliser tel quel)
- `dq4_pc/emu_core.py` + `moteur.py` : le moteur tourne sous Unicorn ; `Moteur.step(...)` avance d'une image, `Moteur.etat` (classe `Etat`) contient l'état décodé : carte à charger, caméra (paquet 10), sprites (12/13), fenêtre de tuiles de la carte du monde (28), icônes (29), maillages de monstres (21/22), fondu, messages, menus (file MenuPort). Les paquets sont décrits dans `notes-technique-portage-dq4.md`.
- Entrées : `GameUpdate(arg1 touches maintenues, arg2 touches pressées)` et messages interface -> moteur (voir `notes-visionneuse-dq4-pc.md`).
- `dq4_pc/donnees.py` + `fld.py` : lecture des données Unity avec UnityPy (cartes `.fld`, textures, feuilles de sprites).
- Test sans écran en cloud : `xvfb-run -a python3 dq4_pc/fenetre.py ... --shot x.png --images N --script "..."` (la visionneuse sert de **référence visuelle** pour comparer).

## Ce qu'on sait du Unity d'origine (inventaire du 30/10/2026)
- Unity 2022.3.62f3, IL2CPP, ARM64 uniquement (`libil2cpp.so` 30 Mo, `libunity.so` 15 Mo, métadonnées `global-metadata.dat` 5 Mo).
- `base.apk/assets/bin/Data/data.unity3d` (8,5 Mo) est **minuscule** : une scène avec une `Main Camera` et un `New Text`, 8 matériaux (Sprites-Default, Button, Menu, SE-GARRIR, polices), 45 shaders, 491 MonoScripts dont **51 classes de jeu** (`Assembly-CSharp`) : `Boot, MainLoop, Global, NativeCall, NativeManager, Field, FldObject, FbxObject, Chara, MeshChara, MeshCapture, BillboardObject, SceneCamera, BackColor, Fade, FrameMaker, MenuParts, MenuMessage, MenuPortSystem, MenuPortItem, MenuPortItemTable, HoppingNumber, Riseup, Sound, Staffroll, TouchPad, InputName, ...`.
- **Conséquence : il n'y a pas de prefabs d'interface ni de scènes à exporter.** Les fenêtres, menus, caméras et la mise en place des scènes sont du **code C# compilé (IL2CPP)** + des données envoyées par le moteur. Un export AssetRipper donnerait cartes, maillages et textures, mais ni la logique ni les fenêtres : il faut réécrire ces ~50 classes (en C# pour Unity, ou en Python pour la piste 1).
- `split_UnityDataAssetPack.apk` : `datapack.unity3d` (64 Mo : 12 267 GameObject, 10 627 Mesh, 4 619 Texture2D, 38 Camera) + `assets/` : `msg` (1002 textes), `sound` (686 `.akb`), `map` (530), `script` (397), `monster` (179 `.dssa`), `effect` (171 `.dssa`), `camera` (163 `.cam`), `trans` (116 `.dssa`), `Large.font`.
- Piège shaders : `datapack.unity3d` est un AssetBundle **construit pour Android** ; ses shaders compilés ne s'affichent pas sous Windows (rose). Prévoir des shaders maison (texture x couleur de sommet, découpe alpha), comme dans la visionneuse.

## Hypothèse et étapes proposées
1. **Installer** Unity Hub + Éditeur 2022.3.62f3 (module Windows), créer le projet `unity_pc/` (rendu intégré « Built-in » ou URP, au choix), hors données du jeu.
2. **Pont** : le moteur Python tourne dans un processus séparé et publie à chaque image l'état décodé (JSON ou binaire) sur un socket local `127.0.0.1` ; Unity le lit (C#) et applique ; les touches repartent dans l'autre sens. Nouveau fichier `dq4_pc/pont.py` (sans toucher à `fenetre.py`). Variante plus tard : Unicorn.NET dans Unity pour supprimer Python.
3. **Preuve 1** : afficher le village (`maout`/`mak1f1`) + le héros dans Unity en chargeant `datapack.unity3d` avec `AssetBundle.LoadFromFile` (fichier extrait localement, voir règles) et un shader maison ; caméra pilotée par le paquet 10.
4. **Preuve 2** : combat `btl_pl_d` + monstres (paquets 21/22 : maillages dynamiques, un octet d'opacité par quad), comparé à la visionneuse (captures côte à côte).
5. **Bilan go/no-go** dans l'issue : fidélité visuelle, 16:9 natif sans bricolage, effort réel, ce qu'il reste à réécrire (fenêtres/menus = `MenuPort*`, `FrameMaker`).

- **Écrit, jamais exécuté dans Unity** (pas d'Éditeur en cloud) : projet `unity_pc/` (notice `unity_pc/LISEZMOI.md`). Les scripts C# compilent contre de fausses API Unity (mcs) et ont été relus à part, mais seule la première exécution sur pdc dira si Unity les accepte.
- **Écart avec l'étape 3 prévue** : la preuve 1 ne charge pas `datapack.unity3d` avec `AssetBundle.LoadFromFile`. Le pont exporte la géométrie des cartes (déjà extraite par `Donnees.carte`) vers `geo.bin` + PNG, et Unity construit les maillages avec le shader maison `DQ4/Unlit`. Raison : testable en cloud, aucun risque de shaders Android roses ni de scripts manquants. Le chargement direct du bundle reste un **essai séparé** (`pont.py --extraire-datapack` copie déjà le fichier ; un menu d'Éditeur qui liste les assets et instancie `mak1f1.fld` avec des matériaux remplacés serait l'étape suivante).
- **Protocole** (détail en tête de `dq4_pc/pont.py`) : TCP `127.0.0.1:7740`, une ligne JSON par image du moteur (caméra, sprites, animations d'objets, bitmap du message compressé, menus en texte), `K <masque>` pour les touches dans l'autre sens. Les menus sont rendus en texte simple (la logique de curseur reste celle de la visionneuse, copiée dans `pont.py`).
- **Retour de test attendu** : `captures/unity/journal.txt` (console d'Unity recopiée), `captures/unity/auto_<carte>.png`, F12 pour d'autres captures ; comparer à la visionneuse (même carte, même moment).

## Règles de travail
- **Aucun contenu Square Enix dans le dépôt** (ni code décompilé, ni textures, ni sons, ni données) : voir `.gitignore`. Les données du jeu sont lues dans les APK de l'utilisateur à l'exécution et extraites dans `dq4_pc/cache/` (ignoré par git). **Ce dépôt est public.**
